# 웅비통신 AI SEO 자동화 시스템

## 역할과 일정
- GitHub Actions의 정적 SEO 점검은 매일 16:20 KST와 관련 변경 시 실행한다. 사이트맵 생성은 별도 기존 워크플로가 담당한다.
- 기존 ChatGPT 예약 점검은 10:00 KST에 실행되는 별도 운영 점검이다. 이미 성공한 Actions를 중복 실행하지 않고 마지막 결과와 변경 사항을 확인한다. 예약 설정 자체의 존재 및 권한은 해당 서비스에서 별도 확인한다.
- 홈페이지, 요금 안내와 렌탈 홈페이지 및 사이트맵에 등록된 정적 페이지의 제목, 설명, canonical, noindex, 파일 존재 및 분석 스크립트 연결을 검사한다. 검사 결과는 Actions 요약과 90일 보관 JSON 아티팩트에 남는다. 기록은 커밋, 실행 ID, 시각, 오류와 경고를 포함한다.
- 정적 검사는 라이브 HTTP, 검색 수집 여부, 검색 순위, 방문 및 실제 전환을 보증하지 않는다. 블로그와 플레이스는 검색 노출 및 공식 관리자 자료를 별도 확인해야 한다.

## 자동 개선과 안전 조건
- 자동으로 수정하는 범위는 기존 사이트맵 갱신 작업이 산출하는 sitemap.xml 및 rental/sitemap.xml에 한정한다. 입력 파일 및 생성기 변경과 결과를 검증하고 변경이 있을 때만 커밋한다.
- SEO 개선은 재현 가능한 문제, 원인과 변경 전후 근거가 있고 기존 기능과 콘텐츠 의미를 보존하는 경우 별도 브랜치에서 수정한다. 데이터·생성물 정합성, 관련 회귀 검사를 통과하고 배포 후 실제 페이지를 확인한다. 실패 또는 불확실한 데이터는 자동 게시하지 않는다.
- 요금, 혜택, 상품·영업정보, 고객정보, 블로그와 플레이스 게시물은 사용자 승인 없이 변경하지 않는다. 검색량이나 전환을 추정하거나 검색 순위 상승을 보장하지 않는다.
- 생성된 페이지의 오류는 원본 또는 생성기를 먼저 수정하고 재생성한다. 오류 원인을 특정할 수 없으면 기록하고 보류한다.

## 실패 및 복구
- 실패한 Actions의 실행 ID, 커밋, 오류, 영향을 받는 경로와 이전 정상 실행을 확인한다. 작업 로그와 아티팩트를 보존하고 실패를 숨기지 않는다.
- 외부 서비스 일시 오류나 권한 문제는 데이터 미확인으로 기록한다. 재실행 전 원인을 확인하고 기존 워크플로의 중복 커밋·경합을 피한다.
- 배포 후 장애는 해당 변경의 영향과 현재 main을 확인한 뒤 해당 커밋을 되돌리고 배포 및 실제 기능을 재확인한다. 비관련 기존 오류는 별도 기록한다.

## 성과 측정 및 연동 상태
- Google Search Console: 속성 소유 확인 및 최소 읽기 권한을 연결한 뒤 확정된 기간의 검색 유형, 기기, 검색어·페이지별 노출·클릭·CTR과 평균 게재순위를 전 기간과 비교한다. 지연 및 작은 표본을 명시한다.
- 네이버 서치어드바이저: 소유 확인 후 수집·색인 및 검색 성과를 해당 공식 도구에서 확인한다. 네이버 블로그와 플레이스는 각각의 공식 관리자 통계를 별도로 확인한다.
- Cloudflare: 수집 Worker 소스와 기존 Access 보호 CRM 관리자 통계 경로를 비공개 운영 저장소에서 확인했다. 관리자 화면의 방문 집계와 자동 보고서 인증은 별개다. 새 비인증 통계 API를 만들지 않으며, 집계 조회 코드·설정·검증은 비공개 운영 저장소의 `Private SEO measurements` 워크플로와 `docs/seo-measurements-setup.md`에서 관리한다. 실측값과 검색어는 공개 저장소/Pages/이 워크플로 아티팩트에 복사하지 않는다.
- 비공개 실측 보고서는 KST 어제까지 7일·이전 7일·28일의 방문/행동 이벤트와 별도의 지연된 Pacific 날짜 범위의 Google 공식 API 검색 성과를 구분한다. Google 읽기 인증과 Cloudflare D1 읽기 전용 인증을 각각 설정해야 한다. 네이버는 공식 관리자 자료를 수동 반입하며, 블로그 통계는 별도다. 소스별 상태/관측일 수/실제 날짜를 확인하기 전에는 연동 성공으로 보고하지 않는다.
- 기존 전환 저장 구조는 전환 세션을 식별하지 않으므로 정확한 세션 전환율을 계산할 수 없다. 전화·카카오·예약 등의 행동 이벤트, 신청성공 이벤트, 실제 상담완료/계약을 구분한다. 빈 결과와 수집 누락을 0건으로 바꾸지 않는다.
- 유입 비교 시 동일 기간, 채널, 기기, 대상 URL, 시간대, 정의 및 지연을 함께 기록한다. 전환율은 동일한 범위의 전환 세션 / 유효 방문 세션으로 계산하되 수집 누락과 중복을 확인한다. 전환 이벤트는 실제 주문 성사와 구분한다.
- 유입 감소만으로 원인을 확정하거나 자동으로 영업 콘텐츠를 변경하지 않는다. 검색 성과, 수집 오류, 페이지 변경, 계절성 및 측정 설정을 함께 조사한다.
